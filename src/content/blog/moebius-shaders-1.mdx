## Inspirations and goals

Jean Giraud worked in science fiction, fantasy and western comics under the name Moebius.
His graphic style was quite recognizable. Specific enough that other artists named him directly:
Otomo cited him as a reference for Akira,
and his concept work inspired the aesthetics of Alien, Tron and The Fifth Element.
His wife said his exceptional precision came from his severe myopia.

## Pipeline

Since my goal is to make 3D look like 2D, I'm using NPR (Non-Photorealistic Rendering).
Most real-time renderers try to imitate how light behaves in the real world.
I go the other way: I don't want the render to look real, it needs to look like a drawing.
To get Moebius's style, I rely on flat colors, ink-like outlines and hatched shadows.

Unity's default lit shaders aim for realism: they blend light, shadows and reflections into smooth gradients.
So all my object shaders are unlit, meaning Unity applies no lighting to them (no light probes and no global illumination).
That leaves the shading to me. Each shader reads the direction of a single directional light
and uses it to blend between a lit color and a shadow color (they are both exposed as inspector properties).

Those shaders only cover the colors, though. Hatching and outlines need to see the whole image
(depth, normals), which an object shader can't do, so they live in a second layer.
Therefore I need to split the pipeline in two.

The first layer is the object shaders (color gradient, bubble, skydome).
The second is a set of fullscreen post-process passes that run after the scene is rendered:
hatching reads the scene color to place hatch lines according to brightness,
and the outline pass reads the depth, normal and color buffers to draw edges on top.

## Outline

Outlines are a fullscreen post-process pass.
It runs after the scene is fully rendered, and detects edges by reading the depth, normal and color buffers.

The starting point was a [tutorial by Digvijaysinh Gohil](https://www.youtube.com/watch?v=nc3a3THBFrg)
covering two well known detection methods: depth-based and normal-based.
The two HLSL snippets below are adapted from it.

### Depth-based detection

For each pixel, the depth buffer stores how far the nearest surface is from the camera.
At the edge of an object two neighboring pixels can have very different values
(say 2 meters on the object, 10 meters on the wall behind it).
A gradient filter looks for these big differences: it compares the depths around a pixel
and measures how fast they change. So a high value means an edge.

The filter used is the Scharr operator, a 3×3 convolution applied to the depth buffer.
Scharr is a variant of the [Sobel operator](https://en.wikipedia.org/wiki/Sobel_operator):
it uses coefficients 3 and 10 instead of Sobel's 1 and 2.
As a result, it reacts more evenly to edges whatever their orientation is (horizontal, vertical or diagonal).
This is called isotropy.

<MathRow
    a="G_x = \begin{bmatrix} -3 & 0 & +3 \\ -10 & 0 & +10 \\ -3 & 0 & +3 \end{bmatrix} * I"
    b="G_y = \begin{bmatrix} -3 & -10 & -3 \\ 0 & 0 & 0 \\ +3 & +10 & +3 \end{bmatrix} * I"
/>

$$
|G| = \sqrt{G_x^2 + G_y^2}
$$

$|G|$ measures how strong the depth change is. A pixel becomes an edge if it exceeds a threshold.

The demo below shows what the depth buffer looks like (closer means brighter).
I use raymarching to fake a scene, but in Unity you don't need that, the buffer already exists.

```glsl live
precision mediump float;
uniform vec2 u_resolution;

float sdSphere(vec3 p, float r) { return length(p) - r; }

// Three spheres at clearly different distances from the camera
float scene(vec3 p) {
    float close = sdSphere(p - vec3(-0.5,  0.1,  1.0), 0.45);
    float middle = sdSphere(p - vec3( 0.4, -0.2,  0.0), 0.35);
    float far = sdSphere(p - vec3(-0.1,  0.4, -0.9), 0.3);
    return min(close, min(middle, far));
}

// Returns ray travel distance, or 8.0 on miss
float getDepth(vec2 uv) {
    vec3 ro = vec3(0.0, 0.0, 3.0);
    vec3 rd = normalize(vec3(uv, -1.5));
    float t = 0.0;
    for (int i = 0; i < 48; i++) {
        float d = scene(ro + rd * t);
        if (d < 0.001) return t;
        t += d;
        if (t > 8.0) break;
    }
    return 8.0;
}

void main() {
    vec2 uv = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;
    float depth = getDepth(uv);

    // Remap to brightness: close = bright, far = dark, miss = near black
    float normalized = 1.0 - clamp((depth - 1.5) / 3.0, 0.0, 1.0);
    vec3 col = depth < 8.0 ? vec3(normalized) : vec3(0.04);

    gl_FragColor = vec4(col, 1.0);
}
```

Now I have everything I need to compute the outlines. The shader below applies the Scharr filter to the depth buffer.
A pixel that passes the threshold turns white and the others stay dark.

```glsl live
precision mediump float;
uniform vec2 u_resolution;

float sdSphere(vec3 p, float r) { return length(p) - r; }

float scene(vec3 p) {
    float close = sdSphere(p - vec3(-0.5,  0.1,  1.0), 0.45);
    float middle = sdSphere(p - vec3( 0.4, -0.2,  0.0), 0.35);
    float far = sdSphere(p - vec3(-0.1,  0.4, -0.9), 0.3);
    return min(close, min(middle, far));
}

float getDepth(vec2 uv) {
    vec3 ro = vec3(0.0, 0.0, 3.0);
    vec3 rd = normalize(vec3(uv, -1.5));
    float t = 0.0;
    for (int i = 0; i < 48; i++) {
        float d = scene(ro + rd * t);
        if (d < 0.001) return t;
        t += d;
        if (t > 8.0) break;
    }
    return 8.0;
}

void main() {
    vec2 uv = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;
    float px = 1.0 / u_resolution.y;

    float dCenter = getDepth(uv);

    // Sample the 8 neighbors
    float d00 = getDepth(uv + vec2(-px, -px));
    float d10 = getDepth(uv + vec2(  0, -px));
    float d20 = getDepth(uv + vec2( px, -px));
    float d01 = getDepth(uv + vec2(-px,   0));
    float d21 = getDepth(uv + vec2( px,   0));
    float d02 = getDepth(uv + vec2(-px,  px));
    float d12 = getDepth(uv + vec2(  0,  px));
    float d22 = getDepth(uv + vec2( px,  px));

    // Scharr gradient: depth change along each axis
    float gx = -3.0*d00 + 3.0*d20 - 10.0*d01 + 10.0*d21 - 3.0*d02 + 3.0*d22;
    float gy = -3.0*d00 - 10.0*d10 - 3.0*d20 + 3.0*d02 + 10.0*d12 + 3.0*d22;

    // Combine both axes into one strength, then compare it to the threshold
    float edge = step(5.0, sqrt(gx*gx + gy*gy));

    float fill = dCenter < 8.0 ? 0.15 : 0.04;
    vec3 col = vec3(mix(fill, 1.0, edge));

    gl_FragColor = vec4(col, 1.0);
}
```

Here is the same logic in the Unity HLSL.

```hlsl
// Shared by the depth, normal and color-based passes
struct ScharrOperators
{
    float3x3 x;
    float3x3 y;
};

ScharrOperators GetEdgeDetectionKernels()
{
    ScharrOperators kernels;

    kernels.x = float3x3(
        -3, -10, -3,
         0,   0,  0,
         3,  10,  3
    );

    kernels.y = float3x3(
        -3,  0,  3,
       -10,  0, 10,
        -3,  0,  3
    );

    return kernels;
}

void DepthBasedOutlines_float(float2 screenUV, float2 px, out float outlines)
{
    outlines = 0.0;

    ScharrOperators k = GetEdgeDetectionKernels();

    float gx = 0.0;
    float gy = 0.0;

    float centerDepth = LinearEyeDepth(SampleSceneDepth(screenUV), _ZBufferParams);

    for (int i = -1; i <= 1; i++)
    {
        for (int j = -1; j <= 1; j++)
        {
            float2 offset = float2(i, j) * px;

            float d = SampleSceneDepth(screenUV + offset);
            d = LinearEyeDepth(d, _ZBufferParams);

            // (row, col) -> (j+1, i+1)
            gx += d * k.x[j + 1][i + 1];
            gy += d * k.y[j + 1][i + 1];
        }
    }

    // Relative gradient: the threshold no longer depends on the distance to the camera
    float g = sqrt(gx * gx + gy * gy) / max(centerDepth, 0.001);

    outlines = step(0.05, g);
}
```

Here is the depth-based pass applied to the test scene in Unity.
It catches most silhouettes, but I ran into two problems.

<Image src={captDepthbasedOutline} alt="Test scene with depth-based outlines only" />

The sphere outline is broken and jagged, and the floor is almost entirely black.
Both come from the same limitation: this pass only looks at distance.
Near the edge of a sphere the depth changes gradually, so the filter sometimes misses it.
And on a floor seen at a grazing angle the depth changes fast from pixel to pixel even though the surface is flat,
so the filter sees edges everywhere.

For now I'm fine with it, since adding normal-based detection on top will fix both.

### Normal-based detection

For each pixel, the normal buffer stores a unit vector pointing perpendicular to the surface.
On a flat area, neighboring pixels have nearly identical normals: their dot product is close to 1.
At a crease, like the corner of a table, neighboring normals point in different directions
and the dot product falls (to 0 for a right angle).

<figure>
    <Image src={dotProduct} alt="Three diagrams showing two surface patches with their normal vectors: coplanar surfaces (n1·n2 = 1), a soft crease at ~45° (n1·n2 ≈ 0.5), and a right-angle crease (n1·n2 = 0)" />
    <figcaption>The dot product of two neighboring normals in three cases: a flat surface (1), a soft crease (around 0.5) and a right angle (0). The threshold sets how sharp a fold must be to get an outline.</figcaption>
</figure>

Now same trick as for the depth, I apply the Scharr filter to these dot product values,
and the creases show up as edges.

```hlsl
void NormalBasedOutlines_float(float2 screenUV, float2 px, out float outlines)
{
    outlines = 0.0;

    ScharrOperators k = GetEdgeDetectionKernels();

    float gx = 0.0;
    float gy = 0.0;

    float3 centerNormal = SampleSceneNormals(screenUV);

    for (int i = -1; i <= 1; i++)
    {
        for (int j = -1; j <= 1; j++)
        {
            if (i == 0 && j == 0) continue;

            float2 offset = float2(i, j) * px;
            float3 n = SampleSceneNormals(screenUV + offset);

            // Dot product measures angular difference from center normal
            float dp = dot(centerNormal, n);

            gx += dp * k.x[j + 1][i + 1];
            gy += dp * k.y[j + 1][i + 1];
        }
    }

    // Lower threshold: dp values are close to 1 everywhere except at creases
    outlines = step(0.2, sqrt(gx * gx + gy * gy));
}
```

I could have done without them, but I wanted bubbles.

### Color-based detection

The fix is to read from the color buffer instead.
Even if they skip depth and normals, transparent objects do render to color.
This third method looks at the four neighbors (left, right, up, down) and turns each color
into a single brightness value (its luminance). Where the brightest and darkest neighbors differ a lot, there is an edge.

```hlsl
float SG_Luma(float3 c)
{
    // Standard perceptual luminance weights
    return dot(c, float3(0.2126, 0.7152, 0.0722));
}

void ColorBasedOutlinesFromSamples_float(
    float4 cL, float4 cR, float4 cU, float4 cD,
    float threshold,
    out float outlines)
{
    float lL = SG_Luma(cL.rgb);
    float lR = SG_Luma(cR.rgb);
    float lU = SG_Luma(cU.rgb);
    float lD = SG_Luma(cD.rgb);

    float lMin = min(min(lL, lR), min(lU, lD));
    float lMax = max(max(lL, lR), max(lU, lD));

    // Local luminance contrast, amplified before thresholding
    float e = (lMax - lMin) * 5.0;

    // smoothstep fades the outline in instead of a hard on/off step, which avoids jagged edges (aliasing)
    outlines = smoothstep(threshold, threshold * 2.0, e);
}
```

<Image src={captColorbasedOutline} alt="Transparent bubble with outlines from color-based detection" />

All three passes combined, the bubble finally gets its outline.

### Outline thickness and screen resolution

I want the thickness of these outlines to be a fixed number of pixels whatever the screen resolution.
But the shader moves around the screen in fractions of its width and height (from 0 to 1),
and a pixel is a smaller fraction at 4K than at 1080p.
A fixed offset would then reach twice as many pixels at 4K. That would make the outline twice as thick!
This is an easy fix: I simply divide the thickness by the screen resolution. Now 1.0 always means one pixel.

<figure>
    <Image src={offsetCorrection} alt="Two side-by-side diagrams comparing a raw offset vs a normalized offset at 1080p and 4K: the raw offset jumps two pixels at 4K, while the normalized offset always jumps exactly one pixel regardless of resolution" />
    <figcaption>The offset is the distance to the neighbor the filter reads. A raw offset covers more pixels at higher resolutions. The normalized offset always covers exactly one pixel.</figcaption>
</figure>

### Limitations

The main limitation is thin geometry.
Small objects like brackets or narrow shelves produce incomplete or missing outlines,
because the depth discontinuity they create is too small for the filter to catch reliably at a
given resolution.

<div class="image-md">
    <Image
        src={captLimitationsExample}
        alt="Scene with small shelf brackets showing incomplete outlines on thin geometry"
    />
</div>

The inverted hull technique would fix this:
each mesh is rendered twice, once normally, then scaled up slightly with backfaces visible,
producing a solid outline that doesn't depend on depth differences in screen space.
It handles thin geometry cleanly regardless of size or distance.
The tradeoff is that it only produces outer silhouettes,
so interior creases and surface details would still need the screen-space pass on top of it.
A hybrid approach (hull for silhouettes, screen-space for interior detail) could combine the best
of both. Maybe a project for later?

## Color gradient

The color gradient shader is the base layer all scene objects build on.
Each object computes its own shading from a single directional light, with no light probes or
global illumination.
The shader maps that lighting to two colors: one for lit surfaces, one for shadow,
with a controllable gradient between them.

### Light mask

The starting point is the Lambert diffuse term, one of the oldest models in rendering.
It states that the intensity of light on a surface is proportional to the cosine of the angle
between the surface normal and the light direction, which in code is a simple dot product.
A surface facing directly toward the light returns 1; edge-on returns 0; facing away goes negative,
clamped to 0 since those faces receive no light.

```glsl live
precision mediump float;
uniform vec2 u_resolution;

float sdSphere(vec3 p, float r) { return length(p) - r; }

vec3 getNormal(vec3 p) {
    vec2 e = vec2(0.001, 0.0);
    return normalize(vec3(
        sdSphere(p + e.xyy, 0.55) - sdSphere(p - e.xyy, 0.55),
        sdSphere(p + e.yxy, 0.55) - sdSphere(p - e.yxy, 0.55),
        sdSphere(p + e.yyx, 0.55) - sdSphere(p - e.yyx, 0.55)
    ));
}

void main() {
    vec2 uv = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;
    vec3 ro = vec3(0.0, 0.0, 2.0);
    vec3 rd = normalize(vec3(uv, -1.5));
    vec3 lightDir = normalize(vec3(1.0, 1.0, 0.5));

    vec3 col = vec3(0.08);

    float t = 0.0;
    for (int i = 0; i < 64; i++) {
        float d = sdSphere(ro + rd * t, 0.55);
        if (d < 0.001) {
            vec3 n = getNormal(ro + rd * t);
            float NdotL = clamp(dot(n, lightDir), 0.0, 1.0);
            col = vec3(NdotL);
            break;
        }
        t += d;
        if (t > 10.0) break;
    }

    gl_FragColor = vec4(col, 1.0);
}
```

In a physically-based renderer, this smooth gradient is the goal.
But this is not what we want. To imitate Moebius's coloring we aim for flat areas of color with a
clean boundary between light and shadow, not a photographic fade.

The simplest fix is a step function: below a threshold the surface is in shadow, above it is lit.

$$
\text{lightMask} = \text{step}(\text{threshold},\ \text{NdotL})
$$

This is the foundation of cel shading. The output is binary: 0 or 1, no in-between.

Already looks nice, and with outlines on top it could pass for a comic-book renderer.
But I wanted more control than that (the shader is called Color Gradient for a reason).
I wanted the option to keep a soft gradient when the material called for it, to move the shadow line
wherever it needed to sit, and to control exactly how sharp or soft the transition should be.

Subtracting the threshold before clamping moves the boundary anywhere on the surface.
Multiplying by a scale factor controls how fast the transition happens.
A high scale compresses the ramp into a near-hard edge; a low scale spreads it into a soft gradient.

$$
\text{lightMask} = \text{saturate}\bigl((\text{NdotL} - \text{threshold}) \times \text{scale}\bigr)
$$

Both spheres below use the same threshold and colors but different scale values:
the top one is soft, the bottom one approaches the hard cel-shading step.

```glsl live tall
precision mediump float;
uniform vec2 u_resolution;

float sdSphere(vec3 p, float r) { return length(p) - r; }

float scene(vec3 p) {
    return min(
        sdSphere(p - vec3(0.0, 0.28, 0.0), 0.22),
        sdSphere(p - vec3(0.0, -0.28, 0.0), 0.22)
    );
}

vec3 getNormal(vec3 p) {
    vec2 e = vec2(0.001, 0.0);
    return normalize(vec3(
        scene(p + e.xyy) - scene(p - e.xyy),
        scene(p + e.yxy) - scene(p - e.yxy),
        scene(p + e.yyx) - scene(p - e.yyx)
    ));
}

void main() {
    vec2 uv = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;
    vec3 ro = vec3(0.0, 0.0, 2.0);
    vec3 rd = normalize(vec3(uv, -1.5));

    vec3 lightDir = normalize(vec3(1.0, 1.0, 0.5));
    vec3 baseColor = vec3(0.76, 0.56, 0.30);
    vec3 shadowTint = vec3(0.55, 0.45, 0.75);
    vec3 lightTint = vec3(1.0,  0.92, 0.75);
    float threshold = 0.15;

    vec3 col = vec3(0.08);

    float t = 0.0;
    for (int i = 0; i < 64; i++) {
        float d = scene(ro + rd * t);
        if (d < 0.001) {
            vec3 p = ro + rd * t;
            vec3 n = getNormal(p);
            float NdotL = dot(n, lightDir);
            // Top: soft gradient (scale 2.5). Bottom: hard edge (scale 20.0).
            float scale = p.y > 0.0 ? 2.5 : 20.0;
            float lightMask = clamp((NdotL - threshold) * scale, 0.0, 1.0);
            col = mix(baseColor * shadowTint, baseColor * lightTint, lightMask);
            break;
        }
        t += d;
        if (t > 10.0) break;
    }

    gl_FragColor = vec4(col, 1.0);
}
```

The last step multiplies the mask by the shadow attenuation from Unity's shadow maps.
A small custom HLSL function reads it from the main directional light:

```hlsl
void MainLightShadowAttenuation_float(float3 worldPos, out float shadowAtten)
{
    float4 shadowCoord = TransformWorldToShadowCoord(worldPos);
    Light mainLight = GetMainLight(shadowCoord);
    shadowAtten = mainLight.shadowAttenuation;
}
```

With this factor in, a surface in the cast shadow of another object has its mask pushed toward 0
regardless of its NdotL.
The function also includes a preview stub that returns 1.0,
since `TransformWorldToShadowCoord` is unavailable outside a real render pass.
